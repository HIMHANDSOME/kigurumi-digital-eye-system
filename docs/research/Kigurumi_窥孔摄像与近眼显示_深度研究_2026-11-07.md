# Kigurumi 双屏数字眼片：窥孔摄像与近眼显示替代方案深度研究

> 版本：2026-11-07（研究归档）  
> 状态：技术选型研究 / **尚未批准改变现有 V1 主线**  
> 适用仓库：HIMHANDSOME/kigurumi-digital-eye-system  
> 研究目标：在屏下摄像头（UDC）缺乏可独立 DIY 的成套方案时，以视窗/窥孔微型摄像头获取外部画面，以佩戴者眼前的独立近眼显示系统提供实时视觉，并适配近视、散光与不同头壳。

## 0. 与现有项目基线的关系及执行摘要

**重要兼容性说明**：截至本报告归档时，仓库 README 的 V1 基线仍为左右各约 7 英寸**真正柔性彩色 E-Ink**（最终物料、驱动资料、授权与供应尚未验证），软件兼容 OLED/LCD；不能把「7 英寸 OLED」当作已确认的项目现状。本研究中的「外侧 OLED」仅表示未来使用 OLED/LCD 的可选配置。对 E-Ink、普通 LCD、普通 OLED，均不能假设摄像头能够透过其显示区成像。摄像头应经**现有透明视窗、专门留出的光学孔或结构缝隙**观察外界；严禁在未经屏厂许可时切割柔性显示面板。该升级为可选「佩戴者视频透视」子系统，**不替代现有 UWB 非光学追踪**、E-Ink Send/Commit 控制、Head Profile 和 Display Adapter 逻辑。

**结论**：

1. **放弃把拆机 UDC 作为项目主路线。** 真正 UDC 依赖专门显示像素排列、透光开口、布线和 ISP 成像恢复，单独买手机前摄通常无法独立实现 UDC。
2. **视觉采集与对外表情显示彻底分离。** 对外的左右数字眼片继续负责角色表情；对内用独立摄像头和近眼目镜显示外界，不应让两种功能互相绑死。
3. **第一版验证**：1 路微型 UVC 或 CSI 摄像头 + Raspberry Pi 5 + 非佩戴式显示器，先完成窥孔几何、弱光、镜头畸变、端到端延迟测量；之后试装一体化 EVF/FPV 近眼光学组件。
4. **正式佩戴路线**：根据头壳内实际尺寸采用带目镜的 micro-OLED/EVF 双目组件；左右独立屈光度补偿、IPD 调节和散光处方插片优先于自研液体透镜。双路摄像头仅在完成硬件同步、几何校准及视差测试后才可作为立体视频透视。
5. **安全前提**：任何未充分验证的电子取景均不能成为在道路、楼梯、人群和有障碍环境中的唯一安全视野。必须有独立的应急观察/快速摘除方案与失电告警；不应把报告提出的 <30 ms 延迟设计目标当作医学安全认证。

## 1. 场景约束、评价指标与安全边界

系统可以拆为：A 外观显示（左右数字眼睛），B 外界采集（1/2 个视窗相机），C 佩戴者视觉（1/2 个近眼光学模组），D 主控及视频路径。当前尚未得到实际头壳内部尺寸、相机与眼睛的空间关系、佩戴者验光处方以及电池/散热数据，下表均属于**选型目标而非已验收指标**。

| 指标 | 原型目标 | 注意事项 |
|---|---|---|
| 实时帧率 | 优先 50/60 fps；必要时评估 90 fps | 1080p60 未必比优化过的 720p60 更低延迟 |
| 端到端 camera-to-eye | 争取中位数 <30 ms，进一步优化到 <15–20 ms | 必须使用实物从光事件到眼端画面测量；不保证安全 |
| 帧时间 | 60 fps 周期约 16.7 ms；30 fps 周期约 33.3 ms | 这一数值不是完整链路延迟 |
| 视场角 | 先以外部约 80–120°、眼端约 35–45°评估 | 不能把不同厂家对角/水平 FOV 混为一谈 |
| 双目机械 IPD | 可参考 56–74 mm 作为设计覆盖目标 | 必须依据人群与头壳空间重新核实 |
| 屈光度 | 以独立调焦覆盖常见近视，另设处方插片 | 散光柱镜/轴位不可仅靠普通球镜调焦补偿 |
| 眼端质量 | 清晰度、畸变、eyebox、eye relief、亮度可调 | 眼镜佩戴可能需要更长 eye relief |
| 安全性 | 可切出、可拆除、告警、外部辅助观察 | 不能让电子失效立即导致无视野 |

用户需最终确认：头壳内部有效纵深/宽高、视窗位置及尺寸、近视球镜/散光/轴位、是否必须戴日常眼镜、使用场景（摆拍/室内行走/演出）、时长、重量和供电预算。

## 2. 屏下摄像头为何不作为首期技术路线

维信诺和京东方公开 UDC 技术强调局部透过率、特殊像素结构/走线、衍射抑制、显示与 ISP 协同。手机拆机前摄只是整个系统的一个部件，既不能直接接普通 7 英寸显示屏，也可能缺乏标准驱动、ISP 调校及连接器资料。中兴 Axon 30 等维修件可以采购，但采购成功不等于可以在树莓派上直接驱动。

- 厂商技术参考：[Visionox UDC](https://www.visionox.com/en/channels/140.html)，[BOE OLED 技术](https://www.boe.com/global/en/Products_OLED.html)。
- 维修件示例：[ZTE Axon 30 前摄拆机件](https://214cellularparts.store/brands/zte)（研究时公开报价约 US$63.23，仅用于说明可买到维修零件，不建议作为 MVP）。
- 替代方法必须**通过真实透明光学孔观察外界**，不可把相机简单贴到不透明 E-Ink/OLED 背后。

## 4. 视窗相机机械布局、遮挡、视差与光学孔

优先布局顺序（以实际壳型为准）：

1. 在左、右**既有可透视视窗附近**分别安装镜头，尽量靠近佩戴者真实眼睛的等效视点，同时避开外侧显示屏、粘胶层和支撑框。
2. 如果只有中央狭缝，考虑鼻梁处单摄；这适合低成本画面验证，但**不能提供真实双目立体深度**。
3. 在数字虹膜附近布孔只有当该处本来就是结构开孔/透明窗口时才可行；不要打穿屏幕、TFT 走线、背板或驱动排线。
4. 远离真实眼视点的额头中央相机容易产生明显高度视差、抓取距离错误与边缘遮挡。

结构侧剖（概念示意，非比例工程图）：

    外界
      │
    [AR 防反光透明保护窗]  ← 可拆洗/防雾
      │
    [遮光消光短筒 + 视窗孔]
      │
    [微型摄像头镜头端]
      └── 薄 FPC / USB 沿眼眶边缘 → 额头/后脑控制板

    [外侧角色数字眼片：E-Ink 或未来 OLED/LCD]
      │         ↳ 只向外显示表情，不承担佩戴者取景
      │
    [内侧独立 micro-OLED + EVF 光学总成]
      │
    [屈光调节 + 可拆处方镜片架]
      │
    佩戴者眼睛

结构要求：镜头周围黑化/植绒、消除柔性屏的光反射、阻断外侧显示串光、镜头保护窗带防雾处理且可维修；预留排线弯折半径、拆装空间和通风路径。保护玻璃、黑色消光筒与镜头焦距的匹配需要实测，不能预先固定孔径 3–8 mm 即认为适合所有镜头。

若双摄组成立体透视：两路摄像头不仅应接近人眼基线，还需校准内参、畸变、相对位姿、采集时间同步与输出到双目显示的视差。**把一台相机画面复制到两个屏幕不等于立体视觉**。低照度、近距离物体、镜头遮挡、不同自动曝光均会影响距离判断。

## 5. 内侧显示路线：直接看屏幕、VR/FPV、EVF 的比较

「直接显示」需区分：
- 将 LCD/OLED 放在角膜前 **20–40 mm** 不加光学元件：对大多数正常眼睛无法舒适清晰对焦，不能作为正式方案。
- 在壳内较远（例如 **15–30 cm**）放一块普通 LCD：可作为基础验证，但有效视场窄、空间要求高，近视或不同调节能力仍需试戴。
- 将 micro-OLED + 专用放大/准直目镜放在眼前：这是 VR/FPV/EVF 近眼光学路线，通过虚像而不是直接聚焦物理屏。

| 比较项 | 头壳内较远普通 LCD | micro-OLED + EVF/FPV 目镜 |
|---|---|---|
| 眼端光学 | 裸眼看真实近处屏幕 | 目镜生成可聚焦的虚像 |
| 尺寸 | 显示面积大，占纵深 | 屏小，镜组占一定厚度 |
| 典型可用 FOV | 受屏到眼距离强烈限制 | 30–50° 常见，按模块规格 |
| 分辨率要求 | 普通小屏可用 | 建议高像素密度 microdisplay |
| 初始集成 | 简单 | 需要合适驱动板和光学模组 |
| 近视适配 | 原眼镜、调整实物距离 | 机械屈光旋钮与处方插片更可控 |
| 成本量级 | 约 $30–100 | 常见 $100–500+ / 双眼，具体询价 |
| 适用阶段 | 台架和观察原型 | 正式穿戴方向 |

## 6. 近视/散光适配（核心需求）

必须把「摄像头对焦」与「眼端显示屈光调节」分开：前者决定摄入画面的清晰度，后者决定佩戴者能否看清投到眼前的虚像。手机端缩放、数字锐化不能代替屈光补偿。

### 6.1 首选：左右独立机械调焦

使用现成 EVF/FPV 目镜的机械轴向调焦，分别控制左右眼虚像焦度。工程探索目标可以设置为约 **-8D～+3D**，但只有实际模块提供对应机械行程、成像质量和标定后才能声明达到范围。增加机械锁定和刻度；双眼不能强制共用一个调焦位置。

### 6.2 必备兼容：可拆式处方镜片

处方插片用于高度近视、散光柱镜和轴位修正。插片架需避免刮碰睫毛、眼镜框和目镜表面；镜片装配需由专业验光数据确定。常见参考处方格式：

- OD（右）：SPH -5.25 D / CYL -1.25 D / Axis 170°
- OS（左）：SPH -4.75 D / CYL -0.75 D / Axis 10°

上述仅为示例，**不是用户个人处方**。普通机械球镜调焦无法消除散光。

### 6.3 必须考虑佩戴普通眼镜

若设计要求佩戴原有眼镜，eyebox 大小、eye relief、面部垫圈和眼镜架空间会显著制约现成 EVF。单独支持 -7D 调焦不等于「兼容戴眼镜」。结构阶段可提供两个配置档案：「裸眼/隐形眼镜 + 目镜屈光调节」与「日常眼镜 + 足够 eye relief/镜片支架」，实际试戴后才能冻结。

### 6.4 其他方案

- **液体透镜**：如 Corning Varioptic、Optotune 能调焦，但目前公开器件多面向机器视觉。直接装在眼前不构成现成眼科级屈光模块，需自行解决孔径、像差和镜组兼容，建议列为远期研究。[Corning](https://www.corning.com/worldwide/en/products/advanced-optics/product-materials/corning-varioptic-lenses.html)
- **软件几何/畸变校正**：对 FOV 匹配、畸变、左右画面 XY/旋转、数字裁剪有效；不能修正真正的屈光不正。
- **佩戴者 Profile**：左右眼屈光设置、处方插片/是否戴眼镜、IPD、eyebox 位置存于佩戴者档案；镜头与视窗相对位置则存在头壳档案，二者分离。

建议首次校准流程：选单目/双目 → IPD 调到能融合 → 遮挡一眼逐眼调焦 → 测试格做水平/垂直/旋转校正 → 在 1–3 m 静物前核对 FOV 和大小 → 原地转头评估舒适与延迟 → 保存头壳+佩戴者组合配置。

## 7. 摄像到显示的数据链路与主控

概念架构：

    左/右窥孔 CSI 摄像头 ─────┐
                                ▼
                         ISP / 主控 / 图像处理
                                │
             去畸变、颜色、裁切、校准与帧缓冲
                                │
              ┌─────────────────┴────────────────┐
              ▼                                  ▼
        左眼 micro-OLED                   右眼 micro-OLED
           ↓ 目镜                               ↓ 目镜
           ↓ 屈光补偿                           ↓ 屈光补偿
        佩戴者左眼                           佩戴者右眼

        手机 App ↔ 配置/健康状态/录像控制
        独立电源管理 → 主控/目镜/摄像头
        外侧数字眼片及 UWB 系统通过既有接口独立运行

| 主控 | 相机输入 | 显示输出 | 工程建议 |
|---|---|---|---|
| **Raspberry Pi 5** | CSI、USB | HDMI、DSI | **首选台架平台**；成熟 Linux 和 libcamera 支持 |
| **Compute Module 5** | CSI / USB，依载板设计 | HDMI / DSI | 正式可穿戴定制 PCB 的首选候选 |
| **ESP32-P4** | MIPI CSI、ISP，须核对固件支持 | MIPI DSI | 适合低功耗单摄单屏 PoC，复杂双目可行性待测 |
| ESP32-S3 | DVP / SPI / USB 部分方案 | SPI / RGB 等 | 不适合高质量低延迟双路 1080p 摄像 |
| 手机 | USB UVC 兼容性由设备决定 | 手机/视频输出 | 软件验证方便，但功耗、延迟与显示兼容需逐机测试 |
| FPGA/专用 SoC | 可自定义 | 可自定义 | 只建议延迟/同步瓶颈被实测证实后选用 |

相关资料：[Pi 摄像头软件](https://www.raspberrypi.com/documentation/accessories/camera-software.html)、[Compute Module 5](https://www.raspberrypi.com/products/compute-module-5/)、[ESP32-P4 数据表](https://documentation.espressif.com/esp32-p4_datasheet_en.html)、[P4 功能开发板](https://documentation.espressif.com/esp-dev-kits/en/latest/esp32p4/esp32-p4-function-ev-board/index.html)。

### 链路比较：模拟 FPV vs 数字 FPV vs 有线 CSI/USB

| 路线 | 优点 | 局限 | 建议 |
|---|---|---|---|
| 模拟 FPV 摄像头 → 模拟视频接收/眼镜 | 原理简单，许多成熟低延迟器件 | 标清画质、模拟干扰；无线电和屏内串扰需要考虑 | 作为低延迟比较基线，但不是首选高质量设计 |
| 成套数字 FPV → 厂商眼镜 | 封装完善，高刷、高画质、较成熟的延迟优化 | 厂商相机/编码/射频/接收/屏幕常是封闭链路；拆改集成困难 | 适合整机体验和光学对照实验 |
| **CSI → Pi/CM5 → HDMI/DSI 光学驱动** | 最可控、可记录和优化各级延迟 | 板级视频时序、ISP、眼端驱动需要验证 | **建议主路线** |
| USB UVC → Pi → HDMI | 插上易用，便于调试 | USB 帧缓冲、MJPEG/H.264 编解码可能增加延迟 | MVP 研发备选/低光基准 |
| MCU/P4 CSI → DSI | 低功耗、短链路潜力 | SDK、ISP、驱动和双路输入实际能力限制 | 后续专项 PoC |

**不要套用厂商提供的「<3 ms」宣传值**到自研链路。厂商数字 FPV 全套设备经过软硬件协同，甚至其所谓 glass-to-glass 统计方法也需查清。CSI 原始像素数据带宽较高，例如 1920×1080×60×16 bit ≈ **1.99 Gbit/s（单路未经压缩 YUV422 纯像素负载）**，双路约 3.98 Gbit/s，尚未计协议开销；USB2 不能直接无压缩稳定搬运该组合。CSI 并不自动等于极低延迟：ISP 帧缓冲、显示排队、曝光时间和实际屏扫描仍需测量。

## 8. 供电、散热、机械与系统安全

- 将主要发热的 SoC、图像处理板和眼端驱动尽量置于额头较上方或后脑、与皮肤隔热；不能把 Raspberry Pi 5 的热源贴近眼部。
- 头壳空间里重点记录连续功耗、峰值电流、表面温度、电池安装位置、气流、体重负担及重心。
- 外侧电子纸高压驱动、视频主控、眼端显示应做好电源隔离与互扰控制；摄像头不应破坏原方案的 E-Ink 安全时序。
- 通讯与外侧 EyeState 控制应在视觉通道失效时正常工作；视觉子系统失效也不能卡住手机表情控制。
- 必须提供无需拆壳即可执行的**快速摘除/翻开/人工观察通道**；失电、镜头遮挡、花屏、图像冻结需要易识别的报警与回退。
- **不得在未验证的情况下依靠摄像头/近眼屏作为上下楼梯、过马路、道路骑行和密集人流中的唯一视野**；有陪同/安全员也不能消除设备本身的失效风险。

## 9. 测试方法、验收记录与工程目标

### 9.1 光子到光子延迟

1. 将 LED 脉冲事件与计时基准置于摄像头视野内；同时使用 240/480/1000 fps 高速相机拍到真实 LED 与内侧显示屏。
2. 计算真实光事件出现与显示屏对应变化的时间差，而不是仅用软件日志中的相机采集回调时间。
3. 至少重复 100 次，统计 P50、P95、P99 与帧间抖动，注明曝光、照度、帧率、分辨率和管线。
4. 比较不同 UVC 格式、CSI、显示刷新率、缓冲深度与自动曝光策略。

工程分层建议：P50 <20 ms 可视为很有竞争力的研发结果，20–30 ms 需继续验证，30–50 ms 适合静态/低速原型，>50 ms 不建议作为移动中的主视觉；**以上仅为项目优先级目标，不是经过认证的生理安全阈值**。参见 [2026 低延迟 HMD 研究](https://arxiv.org/abs/2603.15796) 与 [延迟/眩晕综述](https://www.frontiersin.org/journals/virtual-reality/articles/10.3389/frvir.2020.582204/full)。

### 9.2 画质及光学

- 摄像头：ISO 12233 清晰度、中心/边缘、100/10/1/0.1 lux、暗亮骤变、运动模糊、rolling shutter、镜面反光、防雾、镜头遮挡检测。
- 近眼显示：中心与边角文字清晰度、FOV、畸变、eye relief、eyebox、左右眼融合、IPD、屈光标定精度、亮度和眼镜兼容。
- 视觉几何：静物标定板距离 0.5/1/3 m；测试单摄双屏复制与双摄独立立体显示的区别；近物视差及相机装配偏移。
- 舒适度：静坐 5/15/30/60 分钟的头晕、恶心、视觉疲劳、压迫、重心和距离判断主观评分；逐级过渡到**安全的受控室内**静止/转头/直线短距测试，出现不适立刻停止。

研究依据：[视频透视头显视觉感知与用户满意度](https://www.frontiersin.org/journals/virtual-reality/articles/10.3389/frvir.2024.1368721/full)、[Sony 视频透视的视差与延迟补偿](https://www.sony.com/en/SonyInfo/technology/publications/integrating-both-parallax-and-latency-compensation-into-video-see-through-head-mounted-display/)。

## 10. 预算与阶段实施计划

| 阶段 | 配置 | 工程预算（USD） | 输出 |
|---|---|---:|---|
| M0：光学/单摄功能验证 | B0520 或 IMX219 + Pi 5 + 普通显示器 + 固定托架 + 供电 | **$120–250** | 视频链路、镜头隐藏及延迟基线 |
| M1：单目近眼原型 | CSI 相机 + Pi 5/CM5 + 1 套完整 EVF/micro-OLED 光学总成 | **$250–500** | 单目可调焦、眼镜兼容、人体工学 |
| M2：双目穿戴原型 | 双 CSI + 双 micro-OLED/EVF + CM5 + IPD 滑轨 + 插片 | **$450–900** | 立体画面、独立调焦、机械集成 |
| M3：高阶低延迟 | 双摄同步、IMU、优化管线/SoC/FPGA、高刷目镜 | **$800–2000+** | 延迟、视差与稳定性专项优化 |
| UDC 定制 | 透明像素区 OLED + 专用驱动 + ISP | **需工程级 NRE 询价** | 仅在另立项目后重新评估 |

此处金额是**粗略 BOM 工程估算**，不是厂商整机包报价，也未把原有 E-Ink/UWB 主项目全部开销重复计入；不包括额外人工、结构修改、光学定制、税运、测试设备。

建议的工作包：

- **M0-Gate**：测量可用视窗/相机位置；单摄台架比对 B0066、IMX219、B0520；记录相机尺寸、视场遮挡和延迟。不开展盲目双摄采购。
- **M1-Gate**：核实 near-eye 总成规格及 HDMI/DSI 输入，做有光学目镜的单目可视测试；验证近视调节、散光插片和戴眼镜可用性。
- **M2-Gate**：设计两只镜头安装位、左右目镜 IPD 机构、头壳 Profile 与佩戴者 Profile 分离；实测双摄同步、视差/融合、重量与功耗。
- **M3-Gate**：针对确认的瓶颈优化 ISP 缓冲、帧排队、显示时序及同步；不要在测得链路瓶颈前引入 FPGA。
- **Safety-Gate**：故障注入（掉电、摄像头拔线、画面冻结、白屏、雾气、光学偏移）、快速摘除，以及安全观察通道验收。

## 11. 风险矩阵

| 风险 | 评级 | 原因与缓解 |
|---|---|---|
| camera-to-eye 延迟/抖动 | 高 | 影响身体移动时视觉与真实运动一致性；全链路实测并减少缓冲 |
| 相机视点相对于真实双眼偏移 | 高 | 误判距离、碰撞；靠近自然视点并进行几何校正 |
| 双摄不同步/左右画面不一致 | 高 | 眼疲劳与空间误判；硬件同步与标定 |
| 目镜 eyebox 太窄、戴眼镜眼距不足 | 高 | 长时间佩戴难；先做可拆验光试戴 |
| E-Ink 外侧眼片与光学孔相冲突 | 高 | 外侧眼片是既有主线；不能穿孔伤屏，需改视窗/壳体 |
| 低光和曝光波动 | 中高 | 明暗切换可能短时看不清；曝光策略和遮挡告警 |
| 呼吸雾气/汗液、镜头污染 | 中 | 防雾保护窗、可维护结构 |
| 温度、重心与续航 | 中高 | SoC 后移、分区供电、壳内热测试 |
| UDC 拆机逆向 | 极高 | 驱动/ISP 不明；暂不作为 MVP |

## 12. 最终推荐与决策状态

**推荐方案：外侧角色显示维持现有既定 E-Ink 优先方案，未来适配 OLED/LCD；摄像头经头壳现有视窗/专用开孔采集，初期单 CSI 摄像头 + Pi 5 进行画质及延迟台架验证；正式版优先双 CSI 摄像头 + CM5 + 双套一体化 micro-OLED/EVF 光学总成，配备 IPD 调节、左右独立屈光旋钮与可拆式处方插片。**

建议暂不锁定：某款具体 7 英寸面板、真实针孔孔径、CM5 定型 PCB、双摄同步方案、最终电池容量、FPV 成套眼镜拆机驱动及用于运动中的安全认证。需要测得尺寸、供电与延迟后才能冻结。

**重要：这份文件是研究归档，不代表现有 G0/P0 主项目已自动转向视频透视。** 与 V1 现行项目的批准边界仍以 [仓库 README](../../README.md)、[2026-11-06 可行性复核](Kigurumi_V1.0_可行性与经济性复核_2026-11-06.md) 和 [ADR-0001](../decisions/ADR-0001-risk-gated-v1.md) 为准。
